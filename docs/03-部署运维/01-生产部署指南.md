# 生产部署指南 · video-dedup-station

> 适用 OS：Debian 11+（也兼容 Ubuntu 20.04+）

## 推荐方案：venv + systemd（传统部署）

选择理由：
- 项目依赖极少（Python 标准库 + ffmpeg + 可选 `imagehash`/`Pillow`），无需容器隔离
- MCP 通信只是 HTTP，客户端不关心服务端跑在 Docker 还是裸进程
- 后续扩展功能可直接 `git pull` → 重启 systemd 生效，无镜像重建开销

## 一、服务器依赖

```bash
apt update
apt install -y python3 python3-venv python3-pip ffmpeg git
```

- Python 3.9+（系统默认即可，3.11 实测过）
- ffmpeg → 提供 `/usr/bin/ffmpeg` 和 `/usr/bin/ffprobe`
- git → 克隆仓库

可选（pHash 自检数值，缺则自动降级为 ffmpeg signature 二值判定）：
```bash
# pHash 依赖（安装后 _checks.phash 返回逐帧汉明距离与弱帧占比，否则 method="signature"）
pip install imagehash Pillow
```

## 二、克隆项目

```bash
git clone https://github.com/luckly06/video-mcp.git /opt/video-dedup
cd /opt/video-dedup
```

## 三、创建虚拟环境

```bash
python3 -m venv /opt/video-dedup/.venv
/opt/video-dedup/.venv/bin/pip install -r station/requirements.txt
```

## 四、配置环境变量（下节开）

在 `/opt/video-dedup/.env` 创建：

```bash
# === ffmpeg 路径（Linux 用系统装）===
VU_FFMPEG=/usr/bin/ffmpeg
VU_FFPROBE=/usr/bin/ffprobe

# === 素材与产物目录（确保存在且有读写权限）===
VU_ASSETS=/opt/video-dedup/station/assets
VU_OUTPUT=/opt/video-dedup/output

# === 监听地址（服务器须 0.0.0.0，本地开发用 127.0.0.1）===
VU_HOST=0.0.0.0
VU_PORT=8765
```

```bash
mkdir -p /opt/video-dedup/output
```

## 五、代码微调：让 server 读取 HOST/PORT 环境变量 🔧

> 当前 `mcp_server.py` 的 `__main__` 硬编码 `serve("127.0.0.1", 8765)`，
> 本地开发 OK，但服务器需要 `0.0.0.0`。改为从环境变量读取、保留默认值。

修改 `station/server/mcp_server.py` 末尾 `__main__` 块：

```python
if __name__ == "__main__":
    host = os.environ.get("VU_HOST", "127.0.0.1")
    port = int(os.environ.get("VU_PORT", "8765"))
    serve(host, port)
```

> 这个改动已保证向后兼容：不设 `VU_HOST` 时行为和改前完全一致。

## 六、systemd 服务单元

创建 `/etc/systemd/system/video-dedup.service`：

```ini
[Unit]
Description=video-dedup-station MCP Server
After=network.target

[Service]
Type=simple
User=nobody
Group=nogroup
WorkingDirectory=/opt/video-dedup/station

EnvironmentFile=/opt/video-dedup/.env

ExecStart=/opt/video-dedup/.venv/bin/python /opt/video-dedup/station/server/mcp_server.py

Restart=on-failure
RestartSec=5

# 安全加固
PrivateTmp=yes
NoNewPrivileges=yes

[Install]
WantedBy=multi-user.target
```

启动：

```bash
systemctl daemon-reload
systemctl enable video-dedup
systemctl start video-dedup
systemctl status video-dedup
```

## 七、Nginx 反向代理（可选）

如果你需要域名 / HTTPS / 基础认证 / 限流，配 nginx：

```nginx
server {
    listen 80;
    server_name video-dedup.yourdomain.com;

    # 可加 basic auth（MCP 无内置认证）
    # auth_basic "Video Dedup Station";
    # auth_basic_user_file /etc/nginx/.htpasswd;

    # 禁列出目录
    autoindex off;

    location / {
        proxy_pass http://127.0.0.1:8765;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;  # 去重/裂变可能长时间运行
        client_max_body_size 0;   # 不限制上传（Web 仍走 assets/）
    }
}
```

## 八、MCP 客户端注册

服务端的 MCP URL 为（根据你的 nginx / 直接访问）：

```
http://<服务器IP或域名>:8765/mcp
```

若在 WorkBuddy 中使用，在 `~/.workbuddy/mcp.json` 里添加：

```json
{
  "mcpServers": {
    "video-dedup": {
      "url": "http://<服务器IP>:8765/mcp",
      "transport": "streamable-http"
    }
  }
}
```

> 也可以在本地继续跑 server，不上线。MCP 配置指向本地 `http://127.0.0.1:8765/mcp` 即可。

### 9.1 健康检查

```bash
curl -s -X POST http://<服务器IP>:8765/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"server/discover","params":{}}' | python3 -m json.tool
```

预期返回 `serverInfo.name: "video-dedup-station"`。

### 9.2 探针素材

```bash
curl -s -X POST http://<服务器IP>:8765/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"list_assets","arguments":{}}}' | python3 -m json.tool
```

### 9.3 验证去重

上传一个测试视频到 `station/assets/`，然后在 Web 工位（`http://<服务器IP>:8765/`）点探测 → 去重 → 看自检报告通过。

### 9.4 验证 pHash 自检

```bash
# 确保 imagehash 已装
/opt/video-dedup/.venv/bin/python -c "import imagehash; print('imagehash OK')"
```

若未装，metrics.py 会自动降级到 ffmpeg signature 二值判定（`method: "signature"`），不影响功能。


## 十一、安全注意事项

1. **不直接暴露 8765 到公网**：建议至少套一层 nginx，并加 basic auth 或 IP 白名单。
2. **`delete_output` 受 🔴 硬阻断**：Agent 无法直接调用，必须人工在 Web 工位确认，上线后依然有效。
3. `output/` 目录权限设为 user（`systemd` 用 `nobody` 写了），assets/ 只读。
4. 系统 ffmpeg 版本建议 ≥ 4.2（Debian 11 自带 4.3，足够）。

## 十二、备选方案：Docker（如需跨机器零环境迁移）

虽然推荐传统部署，但若你需要可移植性，Dockerfile 如下（供参考）：

```dockerfile
FROM python:3.11-slim-bookworm

RUN apt-get update && apt-get install -y ffmpeg --no-install-recommends && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY station/requirements.txt station/requirements.txt
RUN pip install --no-cache-dir -r station/requirements.txt

COPY . .

ENV VU_HOST=0.0.0.0
ENV VU_PORT=8765
ENV VU_FFMPEG=/usr/bin/ffmpeg
ENV VU_FFPROBE=/usr/bin/ffprobe

EXPOSE 8765

CMD ["python", "station/server/mcp_server.py"]
```

```bash
docker build -t video-dedup .
docker run -d -p 8765:8765 \
  -v /opt/video-dedup/station/assets:/app/station/assets \
  -v /opt/video-dedup/output:/app/output \
  -v /opt/video-dedup/station/logs:/app/station/logs \
  --name video-dedup video-dedup
```

Docker 方案成本：每次扩展功能要重建镜像，比传统部署多一步 `docker build`。

## 十三、扩展功能的部署流程（两种方式比较）

| 操 作 | 传统部署 | Docker |
|---|---|---|
| 改代码上线 | `git pull` + `systemctl restart` | `git pull` + `docker build` + `docker restart` |
| 加依赖 | `pip install xxx` + restart | 改 Dockerfile + 重建 |
| 回滚 | `git checkout <tag>` + restart | 切 tag + 重建（或用 `docker tag` 回滚） |
| 查看日志 | `journalctl -u video-dedup -f` | `docker logs -f video-dedup` |

**结论**：传统部署更快更轻，推荐以此为默认。Docker 仅在你需要跨多台机器统一下发时考虑。
