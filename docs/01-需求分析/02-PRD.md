## 1. 产品名称

- **产品名称**：视频去重工位 station（Video Uniqueness Station）
- **一句话定位**：一条素材，可编程批量产出 MD5 与视频特征充分互异、观感不崩的多平台分发变体。

## 2. 用户

| 用户层级 | 用户角色 | 关键特征 | 核心诉求 | 需求证据 |
|---|---|---|---|---|
| 主要用户 | 短视频矩阵分发的内容运营者 | 同一条素材要投多平台 / 多账号；日常高频、批量；懂"要规避判重"但不写 ffmpeg | 一键批量出充分互异、观感不崩的变体，避免限流/判重/封号 | 01-需求提示词 §0 场景定义 + §2 "矩阵分发是高频刚需" |
| 次要用户 | 维护/扩展工位的开发者 | 读得懂 `pipeline.py` / `rules.json`，按既有架构扩滤镜链 | 在既有 MCP+Hook 架构上加维度而不破坏走链与审计 | station 已上线，本期即在其上迭代 |
| 非目标用户 | 需要通用视频剪辑（片头片尾/画中画/字幕包装）的创作者 | 目标是"编辑作品"而非"规避判重" | —— | 01-需求提示词 §3 明确永久排除纯编辑功能 |

## 3. 核心场景

- **触发时机**：运营者拿到一条待分发素材，需要为 N 个平台 / 账号各产出一个"看起来一样但被判为不同"的版本时。
- **使用环境**：本地 Windows，浏览器打开 station Web 工位壳（`http://127.0.0.1:8765/mcp` 后端），素材限 `assets/` 白名单目录。
- **前置条件**：station 已启动（`python run.py`）；素材已放入 `assets/`；必须先 `probe_video` 探测（强制走链前置）。
- **使用频率**：高频、批量（一条素材 × N 平台 × M 账号，日常大量重复）。
- **当前做法（AS-IS 基线）**：station 现仅能做画面色彩微调 + 微旋转 + 帧率/码率 + 去水印/裂变；改画面特征维度单一，缺时序类/构图类操作 → 需跳出 station 用 CRVideoMate GUI 手动补做裁剪/变速。

## 4. 核心问题

> 取自上游 Gap 最痛的 2 项，可追溯，不另起炉灶。

| 项目 | 内容 |
|---|---|
| 用户任务 | 一条素材批量产出多个「MD5 与视频特征充分互异、观感不崩」的分发变体 |
| 当前阻碍 | ① 改变视频特征的维度太少（只有画面色彩+微旋转+帧率+码率），缺时序类（变速/去头尾）和构图类（裁剪/翻转）这些去重最有效的手段 → 去重强度不足、变体同质；② 自检只验 MD5 是否变，MD5 变了平台仍可能靠感知哈希判为同源 → 缺「去重是否真有效」的可信度量 |
| 问题严重度 | 高（Gap 表两项均标"高"，直接关联限流/判重/封号） |
| 已有证据 | `station/server/pipeline.py`（现有滤镜链仅覆盖画面调整区一部分）；`CRVideoMate/截屏/原始面板.png`、`操作面板导航栏.png`（参照面板提供裁剪/变速/去头尾等 station 未实现的操作） |
| 不解决的后果 | 变体同质 → 平台判同源 → 限流/封号；且无可信自检，用户不知变体是否"真的不同"，仍需人肉复核或跳出工具补做 |

## 5. MVP 方案

- **一句话方案**：在既有架构上补去重价值最高的 4 类操作（**裁剪、翻转、变速、去头尾截取**），并把自检从「仅 MD5 变」升级为「**MD5 变 + 感知哈希距离达标**」。
- **最小闭环**：选素材 → `probe_video` → 勾选/选档启用维度 → 处理（多维随机受 seed 控制）→ 升级自检（MD5 变 + 感知哈希距离达标 + 分辨率保持 + 时长在允许范围）→ 人工决策交付 / 再生成 → 批量裂变产出充分互异的 N 个变体。
- **核心价值**：变体在「构图 + 时序」两个高价值维度上真正互异，且有可信度量证明"够不同"，降低判重/封号。
- **关键假设**：见 §0；具体阈值与安全区间需真实素材实测标定（见 §16）。

## 6. 本期做什么（P0）

- [ ] **裁剪（crop）**：按比例裁切并缩放回原分辨率（构图类），保持分辨率不变；三档裁切比例 轻 2% / 中 5% / 重 8%（>8% 主体易切、放大糊化，不开放）
- [ ] **翻转（flip）**：水平（hflip）/ 垂直 / 90° 旋转（构图类）；**默认关闭**（含内嵌文字/人脸的素材镜像后违和），仅无字纯画面素材可开
- [ ] **变速（speed）**：`setpts`+`atempo` 音视频同步变速（atempo 保音调，落在 0.5–2.0 单实例区间内），含**最短时长保护**（时序类）；三档 轻 ±3% / 中 ±5% / 重 ±10%
- [ ] **去头尾截取（trim）**：裁掉首尾若干秒（时序类），含**最短时长保护**；三档 头尾各 轻 0.3–0.5s / 中 0.5–1.0s / 重 1.0–1.5s，且成片 <7s 禁截、掐头去尾总量 ≤ 原时长 10%
- [ ] **感知哈希自检升级**：处理后计算变体与原素材（及裂变变体两两之间）的感知哈希距离，判定是否达标
- [ ] **维度编排**：`dedup_video` 支持维度开关 / 强度档；参数随机受 seed 控制，保证裂变变体互异
- [ ] **rules.json 分级**：新增/扩展工具补四级分级 + 走链（仍走 `probe_video` 前置）+ 字段校验
- [ ] **Web 工位 UI**：暴露维度勾选 / 强度档；展示自检结果（含感知哈希距离）

|---|---|---|

## 8. 输入与输出

### 8.1 输入

| 输入项 | 来源与格式 | 是否必填 | 约束 | 缺失处理 |
|---|---|---|---|---|
| 素材文件 | `assets/` 白名单目录内的视频（如 .mp4） | 必填 | 仅限白名单目录，非白名单路径被 Hook 拦截 | `list_assets` 为空 → 提示放入素材 |
| probe 结果 | `probe_video` 输出（分辨率/时长/码率/MD5） | 必填（强制前置） | 未 probe 直接 dedup → 走链拦截 | Hook 拦截并提示先 probe |
| 维度开关 / 强度档 | Web UI 勾选或选档 | 必填（至少 1 维度） | 高破坏性维度（大幅变速/激进裁剪）默认关闭 | 全未选 → 提示至少启用一维 |
| 参数（各维度区间）/ seed | UI 或默认，seed 可选 | 可选 | 落在轻/中/重三档安全区间内（裁剪 2/5/8%、变速 ±3/±5/±10%、trim 头尾 0.3–1.5s，见 §6）；数值待 Q-01/Q-03 实测校验 | 用默认档（中档）；seed 缺省则随机并记录 |
| 裂变数量 N | `batch_fission` 参数 | 可选 | 默认 10、上限 50（防批量占满 output，见 Q-04） | 用默认值 10 |

### 8.2 输出

| 输出项 | 形态与结构 | 质量标准 | 用户后续动作 |
|---|---|---|---|
| 去重后视频 | 落 `output/` 的视频文件 + `job_id` | 分辨率保持、时长在允许范围、可正常播放 | 预览 / 采纳交付 / 再生成 |
| 自检报告 | 结构化 `checks`：`md5_changed` / `resolution_kept` / `duration_close` / **`phash_avg` + `phash_min`（逐帧汉明距离的平均与最小）+ 是否达标（平均 ≥12 且最小 ≥8）** | 每项 true/false + 感知哈希距离数值 | 未达标 → 触发再生成 |
| 裂变变体集 | N 个变体 + 各自 job_id + 两两感知哈希距离矩阵 | N 个变体两两距离均超阈值 | 挑选 / 批量采纳 |
| 审计流 | 实时落 `logs/`（Hook post-audit） | 每次工具调用可追溯 | 复盘 |

## 9. Workflow

细化 TO-BE 中「落到产品/代码里的那一段」，保持现有强制走链与人工决策门。

1. **用户**：Web 工位选素材，点探测。
2. **系统**：`probe_video` 返回分辨率/时长/码率/MD5（走链前置，未探测无法进入下一步）。
3. **用户**：勾选启用维度（画面/时序/构图）或选强度档，设裂变数量 N，可选填 seed。
4. **系统 / 算法**：`dedup_video` / `batch_fission` 按开关拼装 ffmpeg 滤镜链，多维参数受 seed 随机；变速/去头尾套用最短时长保护。
5. **系统**：处理后自检——计算 MD5 变 + 感知哈希距离 + 分辨率保持 + 时长范围；裂变时额外算变体两两距离矩阵。
6. **人工确认（决策门）**：`dedup_video` 无确认字段 → 返回 `input_required` + `requestState`；用户在 UI 确认（`inputResponses.confirm=true` 置于 params 顶层）→ 真执行。
7. **成功分支**：自检全过 → 产物落 `output/` + 展示自检报告 → 用户采纳交付。
8. **失败分支**：自检未达标（如感知哈希距离过近 / 时长越界 / 分辨率变了）→ 提示原因 → 用户调参或换 seed 再生成。
9. **硬阻断**：`delete_output` 即便带人工确认，仍被 Hook[第4级·硬阻断] 拦截。

## 10. AI 起什么作用

本产品的"智能"= 随机参数编排 + ffmpeg 滤镜链拼装 + 效果自检，非大模型生成。据 SKILL 要求逐项说明（不适用项标注理由）。

| 流程节点 | AI/算法 职责 | 为什么用 AI/自动化 | 人工确认点 | 禁止交给 AI 的决定 |
|---|---|---|---|---|
| 维度参数生成 | 生成（seed 控制的多维随机参数） | 人工逐条调 ffmpeg 参数不可扩展；随机编排才能保证 N 变体互异 | —— | 高破坏性维度默认关闭，需人工开启 |
| 滤镜链拼装 | 编排（按开关组合 crop/flip/speed/trim 等） | 组合爆炸，自动拼装比手搓可靠 | —— | —— |
| 去重效果自检 | 判断（感知哈希距离是否达标） | 自动度量替代人肉肉眼比对 | 阈值是否合理由人工标定 | 阈值/安全区间的设定不由算法自定 |
| 交付决策 | 不参与 | —— | **是否交付 / 是否再生成由人工决策**（保留现有决策门） | 交付与删除决定不交给自动化 |

> 说明：本期不引入生成式大模型（无文本/图像生成需求），故 SKILL 的"badcase 需大模型兜底"等项以确定性算法+阈值替代，AI 六项均已按上表逐项落地或标注不适用理由。

## 12. Badcase 兜底

| Badcase | 触发条件 | 检测方式 | 系统兜底 | 用户提示 | 人工介入与恢复 |
|---|---|---|---|---|---|
| MD5 变了但感知哈希仍过近 | `phash_avg` < 12 或 `phash_min` < 8（D-01 口径） | 自检 `phash_avg`/`phash_min` | 标记未达标，不算成功 | "变体与原素材过于相似，建议加维度/调参/换 seed" | 用户再生成 |
| 变速/去头尾把时长砍太短 | 成片时长 < 7s，或掐头去尾总量 > 原时长 10% | 处理前参数校验 + 处理后 `duration_close` | 拒绝执行或钳制到安全下限（至少保留 5s） | "变速/截取超出安全区间，已钳制/请调整" | 用户调参重试 |
| 裁剪/翻转导致分辨率变化 | `resolution_kept=false` | 自检 | 判失败不落交付 | "分辨率未保持" | 用户再生成 |
| 激进裁剪毁观感 | 裁剪比例超安全区间 | 参数校验（默认关高破坏维度） | 高破坏维度默认关，需人工开 | "该维度可能毁观感，需手动启用" | 人工判断后开启 |
| 批量裂变互相同质 | 变体两两距离矩阵存在 `phash_avg` < 12 或 `phash_min` < 8 的对（D-01 口径） | 裂变后矩阵检测 | 标记同质对，建议增维/换 seed | "N 变体中存在过近对" | 用户重跑该对 |
| ffmpeg 处理失败 | 进程非零退出 | 捕获返回码 | job 标失败，不落半成品 | 报错原因 | 用户重试 |

| 视角 | 风险或边界 | 影响 | 应对方式 | 负责人 |
|---|---|---|---|---|

| AI 安全与偏差 | 无生成式模型，主要风险是滤镜链参数越界产出坏样本 | 坏变体流出 | 参数校验 + 自检门 + 人工决策门 + delete_output 硬阻断 | 开发 |

## 14. 用户故事

| 编号 | 故事 | 验收标准 |
|---|---|---|
| US-01 | 作为运营者，我想要对素材启用**裁剪**去重，以便改变画面构图让感知哈希变化更大 | 启用 crop 后，在分辨率保持不变的前提下，输出视频画面构图相对原素材发生可见变化，且 `resolution_kept=true`。 |
| US-02 | 作为运营者，我想要对素材做**翻转**（水平/垂直/90°），以便快速改变画面结构 | 选定翻转方式后，输出画面按所选方向翻转/旋转，`md5_changed=true` 且可正常播放。 |
| US-03 | 作为运营者，我想要对素材**变速**，以便改变时序特征，同时不让视频短到不可用 | 变速倍率落在所选档区间（轻±3%/中±5%/重±10%）时正常输出且音频保持音调（atempo）；成片将 <7s 时系统钳制或拒绝并提示，`duration` 不低于 5s 下限。 |
| US-04 | 作为运营者，我想要**去头尾截取**，以便改变帧序列与时长 | 按所选档裁头尾（0.3–1.5s）；掐头去尾总量 ≤ 原时长 10% 且成片 ≥7s，超限则判失败并提示，`duration_close` 越界不落交付。 |
| US-05 | 作为运营者，我想要处理后看到**感知哈希距离自检**，以便确认变体是否真的够不同 | 自检返回 `phash_avg`/`phash_min` 数值及是否达标；`phash_avg` < 12 或 `phash_min` < 8 时标记未达标并建议再生成。 |
| US-06 | 作为运营者，我想要**批量裂变**出 N 个多维随机变体，以便一次投多个平台/账号 | 裂变产出 N 个变体（默认 10，上限 50），两两感知哈希距离矩阵均达标；存在过近对时标记并提示重跑。 |
| US-07 | 作为运营者，我想要在**确认后**才真正执行去重，以便保留最终决策权 | 无确认字段时返回 `input_required`；确认（`inputResponses.confirm=true` 于 params 顶层）后才落 `output/`。 |
| US-08 | 作为开发者，我想要新维度工具仍走 **probe 前置 + 四级分级**，以便不破坏审计与走链 | 未 probe 直连新工具被 Hook 拦截；`delete_output` 即便带确认仍被硬阻断；审计流落盘。 |

## 16. 假设与待确认项

### 16.1 已定决策（本期基线，可直接进设计/开发）

| 编号 | 决策 | 依据 |
|---|---|---|
| D-01（原 Q1） | **感知哈希方案**：以 Python `imagehash.phash()`（抽帧 + 逐帧 64 位 pHash）为主自检；ffmpeg `signature` 滤镜作可选 pass/fail 兜底（它给二值判定，不适合量化差异）。**阈值反向用**（判"足够不同"）：逐帧汉明距离**平均 ≥12 且最小 ≥8** 才算变体合格；裁剪/变速变体抽帧需按时间比例归一化对齐。新增轻量依赖 `imagehash`（依赖 Pillow） | imagehash 社区 `cutoff=5` 判近重复、阈值 8 判相似，反用取更保守值；ffmpeg 官方 `signature` 文档 + 误报 bug 报告 |
| D-02（原 Q2） | **去重强度档位**：给「**轻 / 中 / 重**」三档预设（用户已定）；每档为各维度参数区间的组合预设，可再暴露"自定义"逐维勾选作高级选项 | 用户拍板 |
| D-03（原 Q3） | **各维度安全区间**（竖屏短视频默认，标"待实测校验"）：<br>· **变速**（`setpts`+`atempo`，保音调，须落在 atempo 单实例 0.5–2.0 硬约束内）：轻 ±3% / 中 ±5% / 重 ±10%<br>· **裁剪**（crop 后 scale 回原分辨率）：轻 2% / 中 5% / 重 8%（>10% 主体易切+糊化）<br>· **去头尾 trim**：轻头尾各 0.3–0.5s / 中 0.5–1.0s / 重 1.0–1.5s；**成片 <7s 禁再截、掐头去尾总量 ≤ 原时长 10%**<br>· **翻转 hflip**：**默认关闭**，仅无内嵌文字素材可选开（文字/人脸镜像易违和），列高破坏维度 | ffmpeg `atempo` WSOLA 0.5–2.0 硬约束 + setpts/atempo 同步公式为文档确证；裁剪/trim/翻转百分比为工程推荐值，须实测校验 |
| D-04（原 Q4） | **裂变数量 N 上限 = 20**（默认 5）：防批量占满 `output/`；`batch_fission` 参数校验拒绝 > 20，UI 限制滑块范围 | 工程默认（本地单机、output 容量与自检耗时权衡），可后续按实际调整 |
