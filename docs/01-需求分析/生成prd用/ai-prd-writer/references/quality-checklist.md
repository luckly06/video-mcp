# AI PRD 质量检查清单

## 必填完整性

- [ ] 是否逐项出现基础七项：产品名称、用户、核心场景、核心问题、MVP 方案、本期做什么、本期不做什么？
- [ ] 是否逐项出现 AI 六项：输入输出、workflow、AI 作用、验证指标、badcase 兜底、风险与边界？
- [ ] 是否包含三段式用户故事及验收标准？
- [ ] 是否包含需求脑图？
- [ ] 非 AI 产品的 AI 六项是否写明“不适用”及理由，而不是省略？

## 决策质量

- [ ] 用户需求是否有证据或明确标为假设？
- [ ] 核心问题是否独立于解决方案？
- [ ] MVP 是否形成完整闭环？
- [ ] 本期不做是否足够明确？
- [ ] 是否说明需求与业务目标或 OKR 的关系？
- [ ] 是否检查用户、业务、资源、现实四个视角？

## AI 设计

- [ ] 输入格式、约束和缺失处理是否明确？
- [ ] 输出结构、质量标准和后续动作是否明确？
- [ ] Workflow 是否区分用户、系统、AI 和人工动作？
- [ ] AI 职责是否具体，是否说明人工确认点？
- [ ] 是否避免把高风险最终决定完全交给 AI？
- [ ] 验证指标是否覆盖用户、业务、AI 质量和安全？
- [ ] Badcase 是否包含检测、兜底、提示、恢复和复盘？

## 可交付性

- [ ] 用户故事是否使用“作为 / 我想要 / 以便”？
- [ ] 每个 P0 能力是否至少有一条用户故事？
- [ ] 验收标准是否可观察、可测试？
- [ ] 脑图是否与正文范围一致？
- [ ] 设计、研发、数据、运营和测试是否能据此行动？
- [ ] 是否集中列出假设、待确认项、负责人和影响决策？

## 禁止项

- [ ] 是否没有编造数据、调研、法规或团队资源？
- [ ] 是否没有使用“智能优化”“体验良好”等不可验收表达？
- [ ] 是否没有只写正常流程而遗漏失败分支？
- [ ] 是否没有把模型或 Prompt 当作完整产品方案？
