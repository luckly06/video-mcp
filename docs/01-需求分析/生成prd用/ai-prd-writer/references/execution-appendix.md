# 完整版 PRD 执行附录

用户要求完整版、研发交付稿或执行清单时，在简版 PRD 后追加以下章节。

## A. 功能详细说明

每个 P0 能力至少写明：

- 功能目的与用户价值
- 页面入口和权限
- 前置条件
- 正常流程
- 异常流程
- 业务规则
- 页面状态：默认、加载、空、错误、禁用、成功
- 数据读写与接口依赖
- 验收标准

## B. 需求待办事项

使用 Markdown checkbox，不使用表格替代执行待办：

```markdown
### 核心 MVP 功能

#### [模块名称]
- [ ] [可实现、可检查、可验收的交付项]
- [ ] [可实现、可检查、可验收的交付项]

### 合规与技术基建
- [ ] [隐私、权限、安全或监控事项]

### P1 扩展功能
- [ ] [后续能力]
```

用户提供进度时使用 `- [x]` 标记已完成项；没有进度信息时默认 `- [ ]`。

## D. 非功能需求

至少检查：性能、稳定性、容量、兼容性、可访问性、安全、隐私、可观测性、成本和 AI 延迟。

## E. 依赖与排期

列出人员、系统、数据、模型、第三方服务、合规审批和上线依赖。没有可靠信息时标记“待评估”，不得自行承诺日期。
