# ⚠️ 模板使用声明（最高优先级）

## 信息优先级（必须遵守）

当多个输入来源存在冲突时，必须按照以下优先级执行：

1. 人工明确指令（最高优先级）
2. 项目文档（PRD、SAD、DD、WBS）
3. UI蓝图提示词（阶段一输出）
4. 模板示例与参考资料（最低优先级）

任何低优先级内容不得覆盖高优先级内容。

## 禁止行为

执行过程中禁止出现以下行为：

- 自行增加业务功能。
- 自行删除需求。
- 自行修改业务流程。
- 自行修改页面职责。
- 自行发明组件规范。
- 自行改变 Design System。
- 自行切换视觉风格。
- 自行添加未指定的第三方设计语言。

## 模板示例声明

本模板中的所有项目名称、页面名称、业务流程、界面示例（例如：飞书）均仅作为 **Prompt 编写示例**，用于说明模板结构与输出方式。

它们**不是当前项目的一部分**，也**不得作为默认实现依据**。

AI 必须将每次执行视为一个全新的项目，完全依据本次输入的项目资料重新理解业务，不得继承、假设或复用模板示例中的任何内容，包括但不限于：

- 业务功能
- 页面结构
- 交互流程
- 页面命名
- 文案内容
- UI 布局
- 组件设计
- 视觉风格

## 唯一信息来源

执行过程中必须严格遵循以下优先级：

### 业务唯一来源

业务需求、页面功能、业务流程、模块划分仅允许来源于：

- PRD
- SAD
- DD
- WBS

不得根据模板示例自行补充、修改、扩展或默认采用任何业务内容。

### 视觉唯一来源

UI 的视觉设计（包括但不限于配色、Design System、组件语言、排版、图标、字体、间距、圆角、阴影、动效、设计语言等）**仅允许来源于人工指定的视觉规范**，包括：

- Design System
- 品牌色板（Color Palette）
- 人工指定的设计风格

模板中的示例项目（例如飞书）**仅可用于理解业务类型，不得作为视觉设计参考**。

AI 不得因为模板示例而默认采用其布局、组件、配色、图标、设计语言或交互风格。

若人工指定 Material Design、Apple HIG、Ant Design、Linear、Notion、Arc Browser、极简风、玻璃拟态等任意设计风格，均必须严格遵循，不得混用或自行发挥。

## 执行原则

执行过程中必须遵守以下规则：

1. 每次执行均视为全新项目，不继承模板示例中的任何项目设定。
2. 业务完全来源于 PRD、SAD、DD、WBS，不得自行推断或补充业务。
3. 视觉完全来源于人工指定的设计规范，不得默认采用模板示例的视觉风格。
4. 模板仅提供生成方法（Method），**不提供项目内容（Project Content）**。
5. 当模板示例与当前项目资料发生冲突时，以当前项目资料为唯一准则。

# 🔄 UI 自动化交付工作流（人工定义风格版）

### 🧱 阶段一：规格定义（人定风格，AI 出图纸）

**输入**

- 原始业务文档（PRD + SAD + DD + WBS）

- <项目>样式和风格.md

  > **人工提供/确认的视觉风格（Design System）**
  >
  > **人工提供/确认的品牌色板（Color Palette）**

- `00-生成UI蓝图提示词.md`

**核心**

AI 负责：

- 解构业务逻辑与页面关系；
- 将业务需求与**人工指定的 Design System**进行绑定；
- 建立统一的视觉规范、组件规范、页面规范与交互规范；
- 输出一份完整的 UI 蓝图（Prompt）。

> **不得引用飞书的视觉风格。**
>
> 飞书仅用于理解业务流程和页面职责，不得作为视觉设计参考。

**输出**

- `UI蓝图提示词.md`
  （封装业务逻辑 + 人工指定视觉风格 + 页面映射关系的"施工图纸"）

------

### 🏗️ 阶段二：代码实现（原型工程化）

阶段二不得重新分析 PRD 设计 UI。

UI 的页面结构、布局、组件、交互均以 UI蓝图提示词 为唯一依据。

如发现蓝图与 PRD 存在冲突，应停止生成并提出问题，而不是自行修改蓝图。

**输入**

- PRD
- SAD
- DD
- `UI蓝图提示词.md`
- `00-生成UI原型的提示词.md`

**核心**

AI 作为纯工程实现者：

- 严格遵循 UI 蓝图中的设计规范；
- 不自行修改视觉风格；
- 不自行重新设计页面；
- 不引入新的组件语言；
- 保持所有页面的设计一致性；
- 将蓝图直接工程化为可运行前端原型。

> **阶段二禁止再次进行设计决策。**
>
> 所有视觉决策均已在阶段一完成；阶段二仅负责高保真工程实现。

**输出**

- 可直接运行的高保真 UI 原型
- 完整覆盖业务流程
- 完全遵循人工指定风格
- 统一 Design System
- 可直接交付开发

## 🎯 工作流内核

> **人类决定审美（Design）。**
>
> **文档决定业务（Business）。**
>
> **阶段一负责建立契约（Blueprint）。**
>
> **阶段二负责工程实现（Implementation）。**
>
> **AI 不负责决定业务，不负责决定风格，仅负责依据契约完成设计与实现。**

## 最终原则

阶段一输出的《UI蓝图提示词》是阶段二唯一设计契约。

除非人工重新修改蓝图，否则阶段二不得重新解释、重新设计、重新定义任何视觉规范或页面结构。

整个工作流遵循：

文档 → 蓝图 → 工程

禁止出现：

文档 → 工程

或

文档 → 工程 → AI再次设计
