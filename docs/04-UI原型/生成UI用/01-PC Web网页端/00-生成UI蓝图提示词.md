## 一，文档使用原则（最高优先级）

本项目的 UI 蓝图不是重新设计产品，而是将现有产品设计进行可视化表达。

生成 UI 蓝图时，必须严格依据以下文档：

### 1. 文档职责

1. PRD（产品需求文档）
   - 定义业务功能
   - 定义用户流程
   - 定义页面能力

2. SAD（系统总体架构设计）
   - 定义系统模块划分
   - 定义各子系统边界
   - 定义页面所属系统

3. DD（系统详细设计）
   - 定义页面职责
   - 定义字段、状态、交互
   - 定义接口及业务流程



### 2.设计原则

UI 蓝图必须来源于以上文档，而不是 AI 自行设计。

任何页面、导航、菜单、按钮、弹窗、流程、交互，都必须能够映射回 PRD、SAD、DD。

严禁：

- 自行新增业务模块
- 自行删除业务功能
- 自行修改业务流程
- 自行增加页面
- 自行删除页面
- 自行调整系统边界

其中：

- PRD 负责确定“做什么”（What）
- SAD 负责确定“系统如何组织”（Architecture）
- DD 负责确定“页面如何实现”（How）

UI 蓝图必须以 SAD 的系统划分作为一级骨架，再结合 PRD 和 DD 补充页面与交互细节，不得仅依据 PRD 自行组织页面结构。

### 3. 文档映射关系

生成 UI 蓝图之前，必须先建立文档映射关系：

PRD 功能
→ SAD 系统模块
→ DD 页面
→ UI 页面

4.覆盖要求

最终生成的 UI 蓝图必须覆盖：

- PRD 中定义的全部业务功能； 
-  SAD 中定义的全部系统模块（作为页面组织与导航骨架）；
- DD 中定义的全部页面职责与交互能力。

### 5. 页面整合规则

DD 中的页面、弹窗、抽屉、对话框、向导等，不要求与 UI 页面保持一一对应关系。

允许为了符合飞书 Web 的交互体验，将多个 DD 页面整合为一个Web 页面，或将部分 DD 页面设计为弹窗、抽屉、侧边栏等交互形式。

但必须保证：

- 不丢失任何业务能力；
- 不改变任何业务流程；
- 每项功能都能够映射回对应的 PRD、SAD、DD。

### 6. 异常处理

若发现文档存在缺失、冲突或无法映射的内容，不得自行假设，必须先向我提出问题，待确认后再继续。

WBS 仅用于了解开发拆分和实现顺序，不得作为 UI 页面设计依据；UI 页面必须以 PRD、SAD、DD 为唯一业务来源。

### 7. 输出前自检（必须执行）

正式输出 UI 蓝图之前，必须完成一次自检，并确认：

- 是否覆盖 PRD 的全部业务功能；
- 是否覆盖 SAD 的全部系统模块；
- 是否覆盖 DD 的全部页面职责与交互能力；
- 是否存在无法映射到 PRD、SAD 或 DD 的页面、功能或交互。

如存在任何未覆盖、冲突或无法映射的内容，不得自行补充设计，必须先列出问题并等待我确认。

## 四，PC Web 网页端端侧专项规范

### 1. 端侧边界

PC Web 网页端的范围是：纯浏览器桌面 Web；禁止混入桌面客户端窗口控制、移动端底部 Tab 或系统手势。

所有页面、导航、弹层、交互和尺寸必须符合该边界。禁止把其他端的窗口、浏览器栏、系统栏、导航方式或手势直接套入本端。

### 2. 典型验收尺寸

必须至少覆盖：1024×768、1280×800、1366×768、1440×900、1920×1080

若 PRD、SAD、DD 或人工确认结果规定了其他尺寸，以已确认内容为准；不得为了适配而删除业务能力。

### 3. 导航与布局基线

- 推荐导航骨架：顶部工作区 + 左侧一级导航 + 二级侧栏 + 主内容区 + 可选右侧辅助面板；
- 页面架构必须先依据 SAD 系统模块建立，再结合 PRD 功能和 DD 页面职责细化；
- 页面整合、拆分、抽屉化或弹窗化必须保留完整业务能力和来源映射；
- 关键任务路径必须可发现、可完成、可返回、可恢复。

### 4. 输入与交互基线

- 鼠标与键盘优先，支持 hover、focus-visible、快捷键和高信息密度操作；
- 必须定义默认、悬停/按下、聚焦、选中、禁用、加载、空、错误、成功、无权限和超长内容状态；
- 危险操作必须按文档要求提供确认、撤销或风险提示；
- 不得仅用颜色表达状态；
- 不得用系统 Emoji 代替图标或插画。

### 5. 蓝图页面模板

每个页面必须逐项描述：

1. 页面编号与名称；
2. 所属 SAD 系统与模块；
3. 对应 PRD 功能；
4. 对应 DD 页面、字段、接口、状态与流程；
5. 目标角色与权限；
6. 页面目标、入口和出口；
7. Layout 结构；
8. 组件与数据清单；
9. 主操作、次操作和危险操作；
10. 弹窗、抽屉、面板或子页面；
11. 全部状态与异常；
12. 响应式 / 自适应规则；
13. 可访问性要求；
14. 来源映射；
15. 验收标准；
16. 未决问题。
