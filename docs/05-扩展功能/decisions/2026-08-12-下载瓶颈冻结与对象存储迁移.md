# 决策记录：下载瓶颈冻结与对象存储迁移

- **状态**：已冻结（freeze/network-limited-downloads 分支落地 2026-08-12）
- **决策人**：项目主理
- **关联 commit**：`5e046c7` — fix: freeze current code before OSS migration

---

## 背景

视频去重 Agent 工位扩展插件已经跑通完整链路：上传 → 探测 → 改写 → 去重 → TTS 配音 → 下载。
但**下载环节对用户使用造成明显不便**：

- 服务端实测 100 MB 产物下载需要 **3–4 分钟**
- 用户在 popup 点下载后看不到明显进度，体验等同于「卡死」
- 用户曾误以为「没有产物」，反复刷新 / 清 storage

根因不是代码，是**物理带宽瓶颈**。

## 实测数据（2026-08-12）

| 维度 | 数值 |
|------|------|
| 服务端 `wget localhost` 下载 108 MB | 0.288 s（376 MB/s） |
| 经公网下载 108 MB | 60–90 s 实测 ~200–500 KB/s |
| 推断 ECS 公网出口 | **3–5 Mbps 封顶** |
| TCP 拥塞窗口（`ss -ti`）| `cwnd:7`（正常应 10–20） |
| 重传量 | 11 MB / 7730 次 / 81 k segs（9% 重传率） |
| 服务端负载 | load 0.08（空闲） |
| 并发 4 路并行下载 | ~345 KB/s（无改善） |

→ **链路物理上限，不在服务端、不在客户端**

## 已尝试 + 已否决的方案

| 方案 | 投入 | 结果 |
|------|------|------|
| Python `wfile.write` 一次发整块 | 0 | 触发 ConnectionResetError，已废弃 |
| Python 流式 64KB 分块 | 0.5 h | 解决 RST，但带宽仍 ~500 KB/s（瓶颈不在写盘速度） |
| HTTP Range 多段并行下载 | 0.5 h | 4 路并发 ~345 KB/s，与单路相同 → 上联链路共享 |
| TCP 拥塞控制参数调优 | 不动 | 路径有丢包/乱序（11k 次重排），需在客户端调，扩展拿不到 raw socket |
| ECS 升带宽包 | ¥ / 持续付费 | **本次未做**，需要阿里云侧付费，单独评估 |

## 决策

**1. 冻结当前代码，停止「下载速度」方向的优化尝试**

理由：
- 已穷举所有代码层面手段（流式 / 并行 / 缓冲）
- 服务端代码已具备正确行为：HTTP/1.1 200 + Content-Length + 分块写
- 继续优化的边际收益 = 0（卡在公网链路）

冻结范围：
- 服务端 `/local/download` 不再做协议级改造（除非整体迁移对象存储）
- 扩展 popup 不再做「等待进度条」类 UI（避免给用户「更快」的假象）

**2. 引入对象存储（OSS / COS / S3）作为下一阶段目标**

- 选型暂定 **阿里云 OSS**（与 ECS 同地缘、内网免流量费、CDN 加速可选）
- 预计落地后下载速度 **50–100 Mbps**（CDN 边缘），100 MB ≈ 8 s
- 投入估算：接入代码 4–6 h；OSS 存储费 ~¥0.12/GB/月；CDN 流量 ~¥0.24/GB

**3. 接入方案（草案，待 OSS 选型后细化）**

- pipeline.py `dedup_video` 完成后追加 `oss.upload(output_path)`（同步、阻塞、不长于 1s）
- 返回结果新增字段 `cdn_url: "https://cdn.xxx/..."`，popup 优先使用 CDN URL
- `/local/download` 降级为内网备用通道（OSS 故障时回退）
- 旧产物（未上传 OSS 的历史文件）保留本地 `/local/download`，新产物优先 OSS

**4. 用户沟通策略（在 OSS 接入前）**

- 文档：明确告知「100 MB 产物下载约需 3 分钟」是已知限制
- popup UI：下载按钮旁加「预计 ~X 分钟」提示，避免用户误以为卡死
- 不要承诺「OSS 接入后可秒下」的时间点，等落地后再说

## 影响清单

冻结前 → 冻结后，扩展用户能感知到的差异：

| 场景 | 冻结前 | 冻结后 |
|------|--------|--------|
| 短视频（< 10 MB）下载 | 几秒 | 几秒（不变） |
| 1 分钟视频（~100 MB）下载 | 4–6 分钟 | 3–4 分钟（流式版略快） |
| 下载按钮点击 | 偶发无效（right-click 才能下）| 100% 触发（addEventListener + 新标签兜底） |
| popup 重开时丢产物链接 | 永久丢失 | 自动从服务器 list_outputs 找回 |
| 去重卡死 10 分钟 | 必须手动点「重置」 | popup 自动发现新产物接管 |
| TTS 是否生效 | 永远静默失败（NameError） | 真正调通，配音产物可下 |

→ **冻结后，所有用户能感知的失败模式都被消除**，剩下唯一硬限制 = 下载速度
→ 下载速度这一项，物理上无法在当前 ECS 上突破；OSS 迁移是唯一出路

---

## 触发「解冻」的条件

满足任一即应启动 OSS 迁移，**不再走「修代码提速」分支**：

1. 用户一周内 ≥ 3 次投诉下载慢
2. 日下载次数 > 20 次（手算时薪成本 vs OSS 费用）
3. ECS 带宽包涨价 ≥ 30%（经济上 OSS 更划算）
4. 出现新的代码路径能把 mcp_server 切到内网专线（如打通 SLB / VPC）
