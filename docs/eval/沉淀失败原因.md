```yaml
task_id: "TASK-2026-VU-P1"
node: extension_stabilization
updated: 2026-08-12

# ---- NEW: recurring failures discovered during extension dev ----

exception_event:
  - id: E1_tier_override
    node_failed: dedup_video._tier
    error_class: DEPLOY_PROCESS_BUG
    status: RESOLVED_FOR_NOW
    symptom: |
      dedup_video calls returned MCP empty response (SEP-2322 no content).
      Server never reached "audit" confirmation because _tier was "warned".
    root_cause: |
      SFTP deploys uploaded pipeline.py and mcp_server.py SEPARATELY.
      pipeline.py's _tier field in tools list was "audit", but the uploaded
      mcp_server.py had an older copy with _tier="warned", overwriting the fix.
    repro_count: "at least 4 times between 2026-08-10 and 2026-08-11"
    resolution:
      action: "always deploy BOTH files together; post-deploy verify via MCP tools/list"
      verify_cmd: >
        curl -s -X POST localhost:8765/mcp -H 'Content-Type: application/json'
        -d '{"jsonrpc":"2.0","method":"tools/list","params":{},"id":"v"}'
        | python3 -c "import sys,json;d=json.load(sys.stdin);
        [print(t['name'],t.get('_tier')) for t in d['result']['tools']
        if t['name']=='dedup_video']"
    lesson: "SFTP overwrite is destructive. Two-file deploy is one atomic unit."

  - id: E2_download_route_missing
    node_failed: /local/download/<filename>
    error_class: MISSING_IMPLEMENTATION
    status: RESOLVED_2026-08-12
    symptom: |
      dedup completed, output file existed on server, but download button returned 404.
      User repeatedly said "没有产物" (no product) even though files were generated.
    root_cause: |
      do_GET → _serve_web only served _WEB_FILES (index.html, style.css, app.js).
      /local/download/<name> was NEVER IMPLEMENTED — not a regression, a missing route.
      This persisted from v1.0 through 6+ user complaints.
    consequence: |
      User cleared chrome.storage.local to "fix" the hang → lost dedupResult link.
      Combined with pHash bottleneck (3-5min wait), user assumed "no product exists."
    resolution:
      - "Added /local/download/<filename> handler in _serve_web (lines ~594-620)"
      - "Path safety: fpath.resolve() must stay inside P.OUTPUT_DIR.resolve()"
      - "unquote() for URL-encoded filenames (Chinese chars → %E5%8E%BB%E9%87%8D)"
      - "Content-Type: video/mp4, Content-Disposition: attachment"
      - "Verified: 200 OK, 108MB served"
    lesson: "Every user-facing button URL MUST be traceable to a server route. "
            "Never assume it exists just because the UI shows it."

  - id: E3_phash_cpu_bottleneck
    node_failed: M.compare_videos (pipeline.py L772)
    error_class: PERFORMANCE_BOTTLENECK
    status: MITIGATED_2026-08-12
    symptom: |
      dedup_video took 4-6 minutes on 2-core ECS for a 50s video.
      During this time: popup showed "processing" with orb-loader, user assumed hang,
      closed popup, cleared storage, reloaded → link lost.
    root_cause: |
      pipeline.py dedup_video runs ffmpeg dedup (1-2min) → TTS mix (30s) →
      M.compare_videos (3-5min CPU 100%, frame extraction + perceptual hash comparison).
      The entire call blocks until pHash completes. No partial result returned.
      On 2-core ECS with ffmpeg already saturating one core, pHash pushes to 100% total.
    resolution:
      - "pipeline.py: dedup_video(skip_phash=False). skip=True wraps pHash in conditional."
      - "skip → phash={skipped:true, passed:null, method:'skipped'}"
      - "all_passed ignores pHash when skip_phash=True"
      - "popup.html: #chk-skip-phash checkbox, default checked → fast path 1-2min"
      - "popup.js: showDedupResult neutral '—' display for skipped pHash"
    lesson: "Self-checks that block the user's core workflow defeat their purpose. "
            "Either async them or make them optional. 3+ min is 'never' for most users."

  - id: E4_env_var_drift
    node_failed: service environment
    error_class: DEPLOY_PROCESS_BUG
    status: RESOLVED
    symptom: |
      Intermittent 503 (VU_HOST lost), ffprobe not found (VU_FFMPEG/FFPROBE lost),
      403 (VU_ALLOWED_HOSTS missing), MIMO_API_KEY missing → TTS 401.
    root_cause: |
      .env file not read in some restarts; systemd Environment= lines
      were incomplete or had syntax errors (missing closing quote on MIMO_API_KEY).
    resolution:
      - "All 5 env vars in /etc/systemd/system/video-dedup.service Environment= lines"
      - "systemd daemon-reload + restart verified"
      - "Post-deploy check: tr '\\0' '\\n' < /proc/<pid>/environ | grep-E 'MIMO|VU_'"
    lesson: "systemd Environment= is the single source of truth for daemon env. "
            ".env files are fragile and should be treated as documentation only."

  - id: E5_tts_key_lifecycle
    node_failed: TTS MiMo API
    error_class: EXTERNAL_SERVICE_ROTATION
    status: RESOLVED_WITH_UI_FALLBACK
    symptom: |
      key1 returned 401 (invalid), then hung (API not responding).
      key2 (sk-cbpqn66amnedyg6sbvqgk24fz8aipdycbekupl44rsra62to) finally works.
      Each rotation required SFTP deploy + restart.
    resolution:
      - "tts_client.py: timeout=15s prevents hanging"
      - "popup.js: TTS 401/error exposed in #dedup-tts-hint (pink) with 降级 advice"
      - "pipeline.py: TTS failure → tts_status=str(e)[:200], output still delivered"
    lesson: "External API keys WILL expire. Expose in UI so user can choose to retry "
            "without TTS instead of seeing a frozen spinner."

rollback_checkpoint:
```
